# Synthetic data only

All records in `fhir/bundle.json` are deliberately fabricated. Never add real patient
records, PHI, credentials, or exports from clinical systems.

The dataset uses a fixed reference date of `2026-10-15`. Medication statuses,
lab flags, susceptibilities, diagnoses, and infection history are supplied fixture
values, not conclusions drawn by the application.

| ID | Scenario |
| --- | --- |
| `PATIENT_001` | E. coli urine culture, previous E. coli UTI, antibiotic allergy, active cephalexin, elevated creatinine |
| `PATIENT_002` | E. coli urine culture with no recorded prior infection or prescriptions |
| `PATIENT_003` | S. aureus wound culture, severe penicillin allergy, active doxycycline |
| `PATIENT_004` | No-growth blood culture, prior Klebsiella UTI, elevated creatinine, incomplete allergy details |
| `PATIENT_005` | Sparse record with an encounter and missing optional history |

Historical microbiology reports and explicit infection-history Conditions are separate.
A positive culture alone does not establish an infection. Missing collections
default to empty lists; an empty allergy list does not assert that a patient has
no allergies. Missing scalar details remain `null` in CLI output.

## FHIR fixture contract

`fhir/bundle.json` is the canonical FHIR R4 collection Bundle. The previous custom
patient JSON and its file loader have been removed. Only the local FHIR service
reads this file. Restart that service after editing fixtures.

| Domain information | FHIR representation |
| --- | --- |
| Synthetic public patient ID | `Patient.identifier`, system ending `/sid/patient` |
| Age | Synthetic `Patient.birthDate`, evaluated at the reference date |
| Active prescriptions | `MedicationRequest.status=active`, inline medication concept, dosage quantity/route/timing |
| Medication allergies | Active confirmed `AllergyIntolerance` with optional reactions/severity |
| Numeric labs | Final/amended/corrected `Observation.valueQuantity` with interpretation codes L/N/H |
| Microbiology | Final/amended/corrected `DiagnosticReport`, linked `Specimen` and organism/susceptibility `Observation` resources |
| Prior infection | Explicit history `Condition` with onset, body site, and recorded organism |
| Diagnoses and encounters | Problem-list `Condition` and `Encounter` resources |

Local terminology and extension URLs use the reserved base
`https://infectious-disease-assistant.example/fhir`; they are identifiers and are
never fetched. They deliberately describe this demo's contract, not a published
implementation guide:

- `/StructureDefinition/synthetic-only`: metadata `valueBoolean=true`.
- `/StructureDefinition/synthetic-reference-date`: metadata `valueDate`.
- `/StructureDefinition/infection-organism` and `/StructureDefinition/previous-treatment`: recorded
  history `Condition` `valueString` extensions.
- `/CodeSystem/observation-category`, code `routine-lab`: distinguishes numeric
  labs from organism/susceptibility Observations.
- `/CodeSystem/microbiology-observation`: `organism`, `susceptibility`, and
  `colony-count`; colony counts preserve the source's textual qualifier.
- `/CodeSystem/culture-outcome`: `growth` and `no_growth` on DiagnosticReport conclusions.
- `/CodeSystem/condition-category`, code `infection-history`: explicit prior infections.

Susceptibility values use the HL7 observation-interpretation codes S/I/R.
Microbiology reports use category MIC. Identifiers preserve original public IDs
such as `MICRO_001_RECENT` while resource IDs use hyphens. No-growth reports have
no organism or susceptibility results. Conditions and encounter values are
recorded fixture facts, not clinical conclusions generated by this adapter.

The adapter supports one specimen and at most one organism per report, numeric
labs, inline medication concepts with one dosage, full birth dates, and relative
references to local resources. It rejects unsupported/malformed structures rather
than treating them as absent. This is a tested Pydantic subset, not a full FHIR
conformance validator. Reference: [FHIR R4 DiagnosticReport](https://hl7.org/fhir/R4/diagnosticreport.html).
